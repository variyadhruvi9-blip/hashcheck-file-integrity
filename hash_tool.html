How does hashing detect changes?

A cryptographic hash function converts any input — a text file, an executable, a video — into a fixed-length string called a digest. Two fundamental properties make hashes useful for integrity checking:

  • Deterministic — the same input always produces the same digest. If you hash a file today and again in a year, an unmodified file gives an identical result.
  • Avalanche effect — flipping even a single bit in the input produces a completely different digest. This makes silent tampering or accidental corruption detectable immediately.

When a software publisher releases a download, they also publish its SHA-256 hash. After downloading, you hash the file yourself and compare — if the digests match, you know the bytes you received are exactly what the publisher signed.

Why are MD5 and SHA-1 considered weak?

A hash function is broken when an attacker can engineer a collision — two different files that produce the same digest. Once a collision is possible, a malicious file can be made to look identical to a legitimate one.

  • MD5 — Collision attacks have been practical since 2004. Attackers have used them to forge SSL certificates and spread malware. Never rely on MD5 for security decisions.
  • SHA-1 — Fully broken in 2017 by the SHAttered attack, which produced two real PDF files sharing the same SHA-1 digest. All major browsers stopped accepting SHA-1 certificates years ago.
  • SHA-256 — No collision attack is known. Its 256-bit digest space (2²⁵⁶ possible values) makes brute-force search astronomically infeasible. Use SHA-256 for all security-critical integrity checks.

Note: MD5 and SHA-1 are still reliable for detecting accidental corruption (download errors, bit-rot) — collisions require deliberate crafting. Their weakness is against motivated attackers.
